# Custom AI View — Custom AI View

Работает в двух видах:

- **Отдельное приложение** — `dist\CustomAIView.exe`, ярлык на рабочем столе.
  Своё окно, без VS Code. Каждое устройство — отдельное окно, можно открыть
  несколько параллельно и поставить рядом айфон и айпад.
- **Расширение VS Code** — вкладка внутри редактора, значок с вашим логотипом слева.

Оба используют один и тот же движок рамок и один и тот же MCP-сервер, так что
ИИ-агент видит и то, и другое одинаково.

## Отдельное приложение

```
CustomAIView.exe                              открыть пустое окно
CustomAIView.exe localhost:5173               сразу открыть адрес
CustomAIView.exe example.com -d ipad-pro-11-m4   на конкретном устройстве
CustomAIView.exe localhost:3000 --windows 3   три окна сразу
```

Настройки — `%USERPROFILE%\.custom-ai-view\settings.json`.
Приложение живёт, пока открыто хотя бы одно окно; закрыли последнее — вышло.

Никаких зависимостей: один файл на 82 МБ, внутри Node и все ресурсы. Нужен только
установленный Chrome или Edge — приложение открывает в нём окно без вкладок и
адресной строки, поэтому оно выглядит как обычная программа.

## Настоящий размер 1:1

В меню зума есть **Actual size 1:1**. Устройство рисуется в его физическую величину:
приложите настоящий айфон к экрану — совпадёт.

Как это работает: монитор сообщает системе свой физический размер, каталог знает
активную площадь экрана каждого устройства в миллиметрах, и масштаб считается из
этих двух чисел. **При этом страница внутри не масштабируется** — она по-прежнему
верстается в свои 402 × 874 логических точки, ровно как на самом телефоне.
Меняется только величина картинки, не вёрстка.

EDID округляет размер панели до целых сантиметров, это примерно полтора процента.
Кому нужно точно — **Calibrate with a bank card**: банковская карта у всех одна
и та же по стандарту, 85.6 мм, подгоняете прямоугольник под неё и масштаб становится
абсолютно точным.

## Размеры — настоящие, а не на глаз

Габариты корпуса, активная площадь экрана и радиус скругления взяты со страниц
спецификаций производителей и проверены встречной проверкой. Безель не подобран
на глаз, а посчитан: корпус минус экран, пополам. Поэтому у iPhone 17 Pro рамка
титановая и толстая, а у Galaxy S24 — тонкая, как в жизни.

Всё это видно в подписи под устройством: логические точки, плотность,
физические пиксели, **миллиметры** и безопасные зоны.

# Что внутри

Вкладка в VS Code, в которой открывается настоящий браузер внутри пиксель-точной рамки
реального устройства: iPhone с чёлкой и Dynamic Island, Samsung с дыркой под камеру,
iPad, MacBook. Сверху — статус-бар с живыми часами, снизу — home-индикатор, по бокам —
кнопки громкости, Action Button и Camera Control. Страница внутри считает, что она
на экране 402 × 874 pt, даже когда рамка нарисована в 55 % масштаба.

## Как открыть

| Действие | Как |
|---|---|
| Открыть браузер | **Один клик по логотипу в левой панели.** Или `Ctrl+Alt+Shift+D` |
| Ввести адрес | Поле в тулбаре. Понимает `example.com`, `localhost:5173` и просто `3000` |
| Найти локальный дев-сервер | **Custom AI View: Preview Local Dev Server…** — сканирует 20 типовых портов |
| Открыть HTML-файл проекта | Правый клик по файлу → **Preview in Device Frame** |
| Выбрать устройство | Кнопка с именем устройства, `Ctrl+D`, или дерево **Devices** в боковой панели |

## Ссылки из VS Code открываются здесь

Кликнули по `http://localhost:5173` в терминале — открылось в этом браузере, а не
в системном. То же для `Ctrl+клик` по ссылке в любом файле. Выключается настройкой
`customAIView.linkHandling`.

Оговорка честная: полностью перехватить **все** ссылки VS Code расширение со стороны
не может — этот хук не входит в стабильный API. Терминал и редактор работают всегда;
превью Markdown и ноутбуки — только в тех сборках, где хук доступен, и расширение
подключается к нему само, если он есть.

## Скриншоты и запись

Кнопка с камерой:

| Режим | Что снимает |
|---|---|
| Whole device | Всё устройство с рамкой, чёлкой и статус-баром |
| Screen only | Только экран, без корпуса |
| Page area | Область страницы, без статус-бара и хрома |
| Full page | Вся прокручиваемая страница целиком |
| Selected element | Выбранный элемент с обводкой |
| Record 5 / 10 s | Анимированный GIF |

Каждый снимок **сразу попадает в буфер обмена** и сохраняется файлом.

Как это устроено: webview физически не может сфотографировать свой кросс-доменный
кадр — браузер не даёт ни рисовать его на canvas, ни читать. Поэтому снимок делает
headless-браузер, который открывает **ту же самую** рамку устройства через **тот же**
прокси и фотографирует её. Поэтому на снимке и чёлка, и часы, и home-индикатор —
всё настоящее. Нужен установленный Chrome или Edge; путь задаётся в
`customAIView.chromePath`, если не нашёлся сам.

## ИИ управляет браузером сам (MCP)

Расширение поднимает локальный контрольный API, а в комплекте идёт MCP-сервер, через который
агент видит и делает то же, что вы. Подключается один раз — блоком в конфиг любого
MCP-клиента:

```json
{
  "mcpServers": {
    "custom-ai-view": {
      "command": "node",
      "args": ["<путь к расширению>\\mcp\\server.js"]
    }
  }
}
```

Команда **Custom AI View: Show MCP Server Setup** отдаёт этот блок с уже подставленным
путём — угадывать, куда распаковалось расширение, не нужно.

Что получает агент:

| Инструмент | Что делает |
|---|---|
| `custom_ai_view_state` | Что открыто сейчас: адрес, устройство, вьюпорт, выделенный элемент |
| `custom_ai_view_open` | Открыть адрес на нужном устройстве |
| `custom_ai_view_screenshot` | Снять экран — **и увидеть картинку**, а не путь к ней |
| `custom_ai_view_inspect` | Разметка, вычисленные стили и габариты любого элемента |
| `custom_ai_view_console` | Консоль страницы и необработанные ошибки |
| `custom_ai_view_record` | Записать GIF |
| `custom_ai_view_devices` | Весь каталог устройств с метриками |
| `custom_ai_view_set_device` | Сменить устройство или ориентацию |
| `custom_ai_view_reload` | Перезагрузить, в том числе жёстко |

API слушает только `127.0.0.1`, проверяет заголовок `Host` и требует токен сессии,
который лежит в `~/.custom-ai-view/control.json` с правами только для владельца.
Выключается настройкой `customAIView.controlApi`.

## Три перезагрузки

Кнопка обновления и стрелка рядом с ней:

| Что | Что делает |
|---|---|
| **Reload** (`Ctrl+R`) | Обычная перезагрузка страницы |
| **Hard reload** (`Ctrl+Shift+R`) | Прокси на несколько секунд требует у сервера свежие копии — и документа, и всех подгружаемых файлов, минуя кеш |
| **Clear cache and reload** | Плюс к этому стирает `localStorage`, `sessionStorage`, IndexedDB, Cache Storage, куки и снимает Service Worker'ы |

Честно про третий пункт: расширение не может очистить собственный HTTP-кеш Chromium —
такого API нет. Но вместе с принудительной ревалидацией и стёртым хранилищем сайта
это и есть настоящий старт с нуля.

## Что именно эмулируется

**Размеры.** Каждое устройство описано логическими CSS-пикселями (то, что видит
`window.innerWidth`), плотностью пикселей, безопасными зонами `env(safe-area-inset-*)`,
радиусом скругления экрана и геометрией выреза. iPhone 16 Pro — это ровно 402 × 874 pt
при `devicePixelRatio: 3`, safe-area 62 сверху и 34 снизу.

**Рамка.** Корпус, безель, кнопки и вырез рисуются на CSS, без картинок — поэтому
остаются резкими на любом зуме и любое новое устройство добавляется одной записью
в каталоге, без файла с артом.

**Чёлка и Dynamic Island.** Ширина чёлки берётся по поколению: 53.5 % ширины экрана
для iPhone X…12 и 42 % для iPhone 13…14 — это те самые «на 20 % меньше», о которых
говорила Apple. Dynamic Island — пилюля 125 × 36.67 pt в 11 pt от верха.

**Статус-бар.** Часы (живые, «9:41» или свои), сигнал, Wi-Fi и батарея, отрисованные
по-разному для iOS и Android. Светлые или тёмные глифы — переключателем.

**Ландшафт.** Не поворот картинки, а честная смена метрик: экран меняет стороны,
вырез уезжает к левому краю, safe-area пересчитывается, кнопки переезжают на новые грани.

**Отступ сверху.** Страница начинается **под** статус-баром, как на настоящем
телефоне: время и значки не налезают на контент. Если нужно наоборот — полноэкранный
режим `viewport-fit=cover`, где страница уходит под чёлку — переключите
**Appearance → Page starts → Edge to edge**. В ландшафте боковые отступы тоже
учитываются: контент не заезжает под Dynamic Island, ушедший к левому краю.

**Браузерный хром.** Кнопка в тулбаре включает интерфейс настоящего браузера —
нижнюю адресную строку iOS Safari, верхнюю панель Chrome на Android, вкладки
Safari на iPadOS, окно macOS со светофором — и **уменьшает видимую высоту страницы**
ровно на высоту этих панелей.

**Цвет статус-бара.** В режиме touch страница сообщает свой цвет фона, и полоса
статус-бара красится в него же — так же, как это выглядит на телефоне, без белой
плашки над тёмным приложением.

## Тач-эмуляция и режим «touch»

Значок в адресной строке показывает режим загрузки:

- **touch** — режим по умолчанию: страница идёт через локальный прокси на `127.0.0.1`,
  и в неё внедряется шим. Только в этом режиме адресная строка **следит за переходами
  внутри сайта** — вы всегда видите, какая страница открыта сейчас, — и работает
  жёсткая перезагрузка.
- **direct** — обычный `<iframe>`. Быстрее, но клики остаются мышиными, а адресная
  строка показывает лишь то, что вы ввели сами: чужой origin свой URL не отдаёт.

Что даёт режим **touch**:

- настоящие `TouchEvent` (`touchstart` / `touchmove` / `touchend`) с корректной семантикой
  `preventDefault` — если страница сама обрабатывает жест, эмулятор в него не лезет;
- перетаскивание пальцем скроллит страницу, с инерцией и затуханием, как на телефоне;
- **`@media (hover: hover)` и `(pointer: fine)` переписываются прямо в CSS** на условие,
  которое никогда не сработает, а `(hover: none)` и `(pointer: coarse)` — на всегда
  истинное. Это единственный способ увидеть мобильную ветку стилей: медиа-запросы
  решаются в движке стилей, и подменой `matchMedia` их не обмануть;
- **`env(safe-area-inset-*)` подставляется реальными отступами устройства** — десктопный
  Chromium всегда отдаёт там ноль, и вёрстка «под чёлку» иначе просто не видна;
- `navigator.maxTouchPoints`, `ontouchstart` и `matchMedia` отвечают как на телефоне;
- вверх уходит мобильный User-Agent вместе с согласованными `Sec-CH-UA` — сервер
  отдаёт мобильную вёрстку, а не десктопную;
- скрываются полосы прокрутки, появляется тап-подсветка и круг под пальцем;
- снимаются `X-Frame-Options` и `frame-ancestors`, поэтому открываются сайты,
  которые обычный iframe показать не может;
- проксируется WebSocket, поэтому hot reload у Vite и webpack продолжает работать.

Режим по умолчанию — `auto`: расширение сначала проверяет заголовки сайта и включает
прокси только если сайт запрещает встраивание. Кнопкой можно включить его принудительно.

Отдельный случай: **обычный `http://` без TLS** вообще не может быть встроен — панель
VS Code является защищённым контекстом, и браузер блокирует такое как mixed content.
Исключение — loopback. Поэтому такие адреса всегда идут через прокси на `127.0.0.1`,
независимо от режима; иначе вы получили бы пустой кадр без объяснений.

### Чего эмуляция не может

Честный список, чтобы не было сюрпризов:

- Мультитач (пинч-зум двумя пальцами) не синтезируется — мышь даёт одну точку.
- `window.open`, `target="_blank"`, `alert`, `confirm` и `prompt` внутри страницы не
  работают: панель VS Code запрещает это своей песочнице, а вложенный кадр может её
  только ужесточить. Ссылки с `target="_blank"` перехватываются и открываются в кадре.
- Камера, микрофон и геолокация недоступны навсегда по той же причине — их нет
  в разрешениях родительского кадра, поэтому передать их вложенному нечем.
- Service Worker и HTTP/2 push через прокси не проходят.
- Сайты, где вы уже авторизованы, в режиме прокси попросят войти заново: куки
  привязаны к origin прокси, а не к настоящему домену.
- Сайты с антибот-защитой могут показать капчу: у прокси другой TLS-отпечаток.
- Снять скриншот содержимого нельзя: браузер не даёт рисовать чужой origin на canvas.
- Адресная строка в режиме `direct` не следит за переходами внутри страницы —
  вложенный кадр чужого origin не отдаёт свой URL. В режиме `touch` следит.

Прокси слушает только `127.0.0.1`, отвечает лишь на запросы со своим `Host`,
а в путь каждого запроса подставляется секрет сессии — снаружи им воспользоваться нельзя.

## Настройки

| Параметр | Что делает |
|---|---|
| `customAIView.defaultDevice` | Устройство при открытии панели |
| `customAIView.startUrl` | Адрес, открываемый сразу |
| `customAIView.clock` | `real` — живое время, `apple` — 9:41, `custom` — своё |
| `customAIView.statusBarStyle` | Тёмные глифы, светлые или без статус-бара |
| `customAIView.statusBarLayout` | `inset` — страница под статус-баром, `overlay` — во весь экран |
| `customAIView.browserChrome` | Рисовать интерфейс браузера и урезать вьюпорт |
| `customAIView.deviceFinish` | Цвет корпуса |
| `customAIView.background` | Фон сцены: студия, тёмный, светлый, сетка, цвет редактора |
| `customAIView.touchEmulation` | `always` (по умолчанию), `auto` или `off` |
| `customAIView.linkHandling` | Открывать ли здесь ссылки из терминала и редактора |
| `customAIView.openOnActivityBarClick` | Открывать браузер сразу по клику на логотип |
| `customAIView.chromePath` | Путь к Chrome или Edge для снимков; пусто — искать самому |
| `customAIView.captureDirectory` | Куда сохранять снимки и записи |
| `customAIView.controlApi` | Включён ли локальный API для MCP-сервера |
| `customAIView.proxyPort` | Фиксированный порт прокси, `0` — свободный |
| `customAIView.userAgent.ios` / `.android` | Свой User-Agent для прокси |
| `customAIView.forceMobileViewport` | Вставлять `meta viewport` в страницы без него |
| `customAIView.gridDevices` | Состав стены устройств |

### Про `forceMobileViewport`

По умолчанию **выключено**, и это осознанно: страница без `<meta name="viewport">`
раскладывается в 980 CSS-пикселей и масштабируется под ширину экрана — ровно так же,
как это делает настоящий мобильный Safari. Так вы видите реальную проблему, а не
её замаскированную версию. Включите параметр, если хотите принудительно навязать
`width=device-width`.
